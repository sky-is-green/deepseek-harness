# HiveBench Studio: Multi-Agent DAG Work Plan

Coordination plan for building HiveBench Studio: DeepSeek Harness (`dsh`) extended with local-first LLM hosting (LM Studio-class functionality), inbound model serving, and the Hive context-curation sidecar plus benchmark protocol. Any number of agents may work concurrently, scheduling is governed by the task-dependency graph and the coordination protocol below, not by worker count. This file is the single coordination point: each worker reads it, claims one `[Available]` task whose blockers are cleared, declares its `Target_Files`, and touches nothing else. Historical note: prior six-track numbering folded in as T1 → Lane A, T5 → Lane B, T0/T2/T3/T4 → Lane C; the three-lane model was superseded by this DAG protocol on 2026-08-25 (lane slugs survive as domain prefixes).

## Coordination protocol (v2, adopted 2026-08-25, supersedes temporal wave scheduling)

The task board is a Directed Acyclic Graph. Workers are not assigned to lanes or waves; they consume the frontier.

**Rule 1: Dependency-graph scheduling.** Scan the task board for rows with `Assignment_Status = [Available]`. A row is claimable **iff every Task_ID in its Blockers column is `[Completed in Round N]`** for some landed round N. Waves below are derived views of the graph kept for reading order; they impose no timing. Never claim a task whose blockers include an unlanded row.

**Rule 2: File-system containment.** Before initializing work, register `Target_Files` (the explicit list of paths you will create or modify) into your row **and** write `.claims/<Task_ID>.json` (`{"task_id","worker","target_files":[...]}`) — the lefthook pre-commit **claims gate** (`scripts/check-claims.mjs`) rejects any staged file not covered by a registered claim, enforces the hotspot single-commit rule mechanically, and rejects `vendor/**` outright. Then spawn an isolated sandbox:

```
git worktree add ../hivebench-<Task_ID> -b hive/<Task_ID>
```

You are forbidden from modifying any path not in your row's `Target_Files`. If scope grows mid-task, amend the row first and re-check it against open claims, silent expansion is a planning bug. Prefer additive new packages over editing existing ones; new directories never conflict.

**Rule 3: Hotspot serialization & single-commit protocol.** Hotspots (registry below) are global configuration files protected by exclusive locks. If your `Target_Files` intersect a hotspot: acquire the lock by writing your worker ID + date into that row's Holder cell *before editing*; while held, your commit payload must contain **only** that hotspot file's modification, never bundle framework/UI logic into a hotspot commit. The lock releases when the commit lands on the integration branch.

**Rule 4: Automated verification matrix (definition of done gate).** A task may not be declared complete or pushed for integration until every gating command exits 0 from the task worktree: focused tests over owned paths (`pnpm vitest run <owned spec paths>`), scoped lint (`oxlint` over touched dirs), and per-package type/build validation (`tsc -b <package>` / package-scoped build). Repo-wide `typecheck`/`lint`/`build` remain blocked by the known clean-tree infra issue (see working notes), until that lands, per-package isolation is the accepted gate, and integration rounds run the full matrix. Every completed task ships a structural Agent Note at `.agents/notes/<domain>-<Task_ID>.md` inventorying changed interfaces, models, or hooks before requesting review ([note policy](.agents/notes/README.md)).

**Standing clauses carried over:** read [AGENTS.md](AGENTS.md), [packages/AGENTS.md](packages/AGENTS.md), and [docs/architecture.md](docs/architecture.md) first; they bind. Commit small and often to your task branch. Wire contracts freeze when a second consumer starts depending on them; changing a frozen contract needs a board entry plus sign-off from consumers. Build user-visible surfaces as plugins registering into documented slots rather than editing shared client infrastructure.

## Domains (naming only, no scheduling rights)

Domains are attribution prefixes for Task_IDs, branch names, and note filenames. They no longer reserve directories; containment is `Target_Files`-based per claim. The default ownership below is guidance for registering `Target_Files`, overridable by any claim that registers honestly.

| Domain | Mission | Default Target_Files guidance |
|---|---|---|
| `engine` | Local model hosting and serving: catalog, download, load, generate, embed, inbound OpenAI-compatible endpoint | `packages/models/**`, `packages/host/openai-endpoint/**`, `packages/llm/llm-pi-ai/**` (local-route changes) |
| `studio` | Everything the user sees: model manager cards, palette, search, fork, process panel, transfer, kill switch, agent-preset management | `packages/client/ui-*` packages |
| `xray` | Dev observability, Hive sidecar and curator, bench gating, preset trainer, generators | `sidecar/**`, `packages/hive/**`, `packages/test-support/hive-mock-server/**`, `packages/client/ui-devtools-*`, `packages/runtime-diagnostics/**`, `scripts/` generators, `packages/preset/preset-trainer/**`, `apps/cli/config/agent-presets/**` |

Shared-infrastructure client packages (`ui-runtime`, `ui-renderer`, `ui-primitives`, `ui-layout`, `ui-conversation`, connection, modules) belong to no domain; any worker needing a change claims a task whose `Target_Files` cover it (hotspot rules apply where listed). Core packages (`core/`, `session/`, `subprocess/`, `fs/`, …) are frozen reference; extending one means an additive sibling package where possible, otherwise a registered claim.

## Hotspot registry (exclusive global locks)

Hotspots are protected by exclusive locks per Rule 3: write your worker ID + date into the Holder cell **before editing**, commit the hotspot file alone, and the lock releases on merge.

| Hotspot | Rule |
|---|---|
| `pnpm-lock.yaml`, root `package.json` | Claim, add dependencies, single-file commit, release. Never bundled with other changes. Holder: none |
| `tsconfig.host.json`, `tsconfig.client.json`, project-reference aggregates | Same lock protocol; register new packages one PR at a time. Holder: none |
| `packages/bundle/web-app/**` (manifest + patch rows) | Shared client-infrastructure surface: one additive registration per claim, committed alone, released after. Holder: none |
| Generated catalogs (`docs/tool-catalog.md`, `docs/config-catalog.md`, `docs/event-producer-consumer.md`, `docs/module-graph.md`, subsystem pages) | The worker whose source change regenerates them commits them immediately after regenerating and rebases onto latest integration before pushing |
| `.agents/notes/**` | Any worker, own files only; filename prefix `<domain>-<Task_ID>-<slug>.md` |
| `vendor/**` | Nobody; vendored framework changes go upstream through the sync procedure |

## Integration rounds

Rounds are triggered by any of: (a) a batch of tasks reaching `[Completed]` whose dependents are waiting to unblock, (b) a hotspot conflict that cannot wait, or (c) an explicit call from any worker when merge risk has accumulated. The performing worker merges all completed task branches into the integration branch in dependency-depth order (standing heuristic: sidecar/contract rows first, then engine, then studio), resolves conflicts, runs the full matrix (`pnpm install && pnpm run build && pnpm run test && pnpm run typecheck && pnpm run lint`), fast-forwards `hive-studio`, and posts the round number on the board. Other workers immediately rebase their task worktrees. Two workers editing the same file between rounds is always a planning bug, split the row instead of coordinating in flight.
